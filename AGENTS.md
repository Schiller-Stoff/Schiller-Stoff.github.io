# AGENTS.md

## What this is

Static single-page personal site (Linked Data CV) for Sebastian David Schiller-Stoff. There is no package manager, build, test, lint, or CI workflow; assets are served as plain files from the repo root. Origin is `Schiller-Stoff/Schiller-Stoff.github.io`; `master` is the published branch (GitHub Pages settings live outside the repo).

The published design is V4, “Evidence, clearly presented”: a neutral institutional palette, sans-led typography, and evidence-first hierarchy aimed at research directors, programme managers, cultural-heritage institutions and hiring managers. The `redesign` branch adds V5, “Living evidence”: one finite hero scene (typed sentence, linked-data graph, profile settle), one-pass structural rule draws, and restrained interaction feedback layered on the unchanged V4 structure. V6, “The page answers”, promotes the typed line to a rotating, pausable focus line, adds arrival acknowledgement, copy/submit feedback, a scroll-drawn CV spine and a footer graph bookend. V7, “Blue ink”, reskins the same structure and motion: a white canvas, one ultramarine accent, serif statements, pills and circles, and an ultramarine footer. V8, “Depth, restrained”, adds the page's only scroll-linked parallax (a 48px drift of the hero graph), an ultramarine fill on the register arrow, a white bridge band after the register, and `storymap.html` — a static, dependency-free data study of DERLA's 4,393 documented places of remembrance. `redesignv8.md` is the current motion record, `storymap-draft.md` the storymap scope and data record, `redesignv7.md` the previous visual rationale, `redesignv6.md` the previous motion record, `redesignv5.md` the V5 record, `redesignv4.md` the structural rationale, `redesignv3.md` the previous direction and `redesignv2.md` / `REDESIGN-PLAN.md` are superseded history.

## Source of truth

- `index.html` (~1,500 lines): the whole page. Sections in order: hero (`#top`), credibility strip, selected outcomes (`#case-studies-section`, with the `#announcements` alias), capabilities (`#services-section`), working method (`#approach-section`), project register (`#portfolio-section`), bridge band (`.bridge`, no id, links to `storymap.html`), knowledge transfer (`#teaching-section`), CV (`#cv-section`), contact (`#contact-section`), imprint (`#imprint-section`), footer. All ids and the fragment links between them are part of the public contract — do not rename them.
- `storymap.html`: a second, standalone page — “The Memory Landscape”, a static data study of DERLA. Same fonts, tokens and stylesheet, its own masthead/footer, five chapters, an inline 47KB SVG map of all 4,393 records, and **no JavaScript at all**. Its own ids (`ch-01`…`ch-04`, `colophon`) are local to the page; it links back to `index.html` and out to DERLA.
- `css/custom-styles.css`: the only stylesheet and the de facto source. It starts with one `:root` token block (white canvas and surface, paper/bed/tint surfaces, ink, one ultramarine action plus positive/error, ultramarine-footer on-dark colours, two typefaces, six text sizes plus six display roles, five leading and three tracking roles, an eight-step 4px spacing scale, 0/2px/pill/circle radii, 1px/2px rules, motion). Motion tokens are `--dur-fast`/`--dur-base`/`--dur-draw`/`--dur-scene`/`--dur-arrive`/`--dur-sweep`/`--dur-press`, `--ease-standard`/`--ease-enter` and `--shift-sm` (3px)/`--shift-md` (6px); `--dur` and `--ease` remain aliases for V4 component transitions. Eighteen sections style the CV; §19 styles `storymap.html` under `sm-*`/`map__*` only; §20 forced colours, §21 motion, §22 print. Edit this file directly; do not add a second stylesheet.
- `js/site.js`: all behaviour, vanilla JavaScript, loaded with `defer`. Guarded modules: footer year, header scroll state, non-modal mobile navigation, scrollspy, project filters/load-more, Formspree form, rotating hero focus line, arrival acknowledgement, copy e-mail, decorative rule observer. `storymap.html` loads no script at all — the page has to be complete without one.
- `tools/storymap/build_map.py`: the offline map generator behind `storymap.html`. Extracts the inline FeatureCollection from DERLA's public map page, filters malformed coordinates, projects to Albers and splices one inline SVG between the `map:begin` / `map:end` markers. Run it by hand (`--map-html` / `--natural-earth` accept saved copies); its output is committed, like the WebP derivatives. Never run it at page load.
- `fonts/`: two self-hosted OFL woff2 files — `ibm-plex-sans.woff2` (variable 400–600, the UI face) and `source-serif-4.woff2` (variable, the statement face: wordmark, `h1`, `h2`, the two editorial `h3` roles and the hero `em` reset). No CDN fonts, no mono face.
- `images/`: WebP content assets plus `og-cover.jpg` for social previews. The hero portrait is `images/profile/sebastian-stoff.webp`.
- `redesignv8.md` is the current motion and depth record (hero graph drift, register arrow fill, bridge band) with its review verdict and fallbacks. `storymap-draft.md` is the storymap's data, licence and editorial record; the Graz walk stays there as a deferred appendix. `redesignv7.md` is the previous visual rationale and implementation record. `redesignv6.md` is the previous motion record. `redesignv5.md` is the V5 motion record. `redesignv4.md` is the V4 structural rationale. `design-refactor.md` is the implemented design-system refactor: tokens, labels/tags, colour semantics, media derivatives, register density, filters and code cleanup. It is the reference for the base token values and component decisions.

## Editing gotchas

- **No build step.** Change `index.html`, `storymap.html`, `css/custom-styles.css`, and `js/site.js` directly. Do not introduce a bundler, framework, package manager, or CDN dependency. `tools/storymap/build_map.py` is an offline generator for one committed SVG fragment, not a build pipeline.
- **No content reveal.** Content, images, evidence and controls are never hidden pending JavaScript or scroll; the only progressive-enhancement switch for controls is `html.js-ready`. Motion may gate **decorative ink only**: `html.motion-ready` (added by `initDrawnRules`) hides the evidence-band rule, the delivery-path rule, section eyebrow markers and the footer graph until an `IntersectionObserver` adds `.is-drawn`, and the observer unobserves each target after one pass. `html.typed-ready` (added by `initTypedFocus`) reveals the caret and the pause control; without it the first phrase is a complete static line. Never add a page-wide scroll-reveal system, parallax on reading matter, count-up metrics or perpetual animation. The only scroll-linked motion on the CV is the hero graph drift (§21): decorative ink, 48px, desktop only. The only `infinite` animations are the caret blink (removed when rotation settles) and the submit sweep, which exists only while `is-sending` and is not applied under reduced motion.
- **Visual system (V7/V8):** one accent (`--action`, ultramarine) on a white canvas; `--surface-paper` marks alternating bands and hover, `--surface-bed` sits behind media, `--surface-tint` is the single award-note surface. Serif is limited to the wordmark, `h1`, `h2` and the two editorial `h3` roles — on both pages, so the bridge band's `h2` and the storymap's `h1`/`h2` qualify and nothing else does (chapter numerals and the storymap's stat counts are sans, tabular). Surfaces are square (`--radius: 0`), tags use `--radius-sm` (2px), controls are pills (`--radius-pill`), and the portrait, eyebrow node, nav toggle, typed toggle and register arrows are circles. Section heads are a two-column grid above 1120px (`"eyebrow eyebrow" / "title intro"`, 0.57/0.43, baseline-aligned) and collapse to a block at ≤1120px. The header has no shadow: scrolling deepens only its bottom rule. The footer is an ultramarine field with a white serif wordmark and a periwinkle graph — it stays the page's only full-bleed colour field; the bridge band is white on purpose. Nav current/hover stays weight 500 so scrollspy cannot shift layout; blue plus the underline carry the state.
- **Hero typed focus line:** only `.hero__focus-line` rotates; `h1` stays static. The visible span is always `aria-hidden` and one `.visually-hidden` sentence carries the same claim for assistive technology. `initTypedFocus()` reads the other phrases from `<script type="application/json" data-typed-phrases>`, reserves the tallest phrase height on `.hero__focus-line` before clearing the span, types at 26 ms (140 ms after `[.,;:—–·]`), holds 6 s, erases at 12 ms and advances. It never simulates mistakes and never loops without the control. Rotation stops when the tab is hidden, the hero is off screen (one `IntersectionObserver` on `#top`), reduced motion is requested, or the user pauses; the pause control completes the current phrase and swaps its label/icon. Reduced motion, print and a module failure all leave phrase 1 as a complete static line with no caret and no button.
- **Arrival acknowledgement:** `initArrival()` delegates one `click` listener for fragment links inside `.nav`, `.footer-nav` and `.hero__actions`, adds `.is-arrived` to the destination section for 900 ms, and forces a reflow so a repeated click restarts the 700 ms rule draw under the `h2`. If the target is off screen it waits for one `scrollend` (900 ms fallback) so the smooth scroll does not spend the draw; that listener is transient, not scroll math. It never moves focus, never runs on load, the skip link or reduced motion, and removes its own class.
- **Copy e-mail:** `initCopyEmail()` reveals the button, uses `navigator.clipboard.writeText` with a hidden-textarea `execCommand` fallback, swaps Copy → Copied with a drawn check for 2 s, and never replaces the `mailto:` link.
- **Scroll-drawn CV spine:** `.cv-list::before` fills and `.cv-entry::before` markers resolve from rule grey to action blue with `animation-timeline: view()` only, inside `@supports` and `prefers-reduced-motion: no-preference`. Without support, on ≤900px, in print and under reduced motion the spine is a complete static rule.
- **Footer graph:** a 9-node/10-edge inline SVG echo of the hero field, `aria-hidden`, `pointer-events: none`, drawn once by the shared rule observer, hidden at ≤900px, in print and in forced colours. It is periwinkle (`--tint`) at 0.45 opacity on the ultramarine ground. It must never change footer dimensions.
- **Hero graph:** inline SVG in `.hero__graph`, 12 nodes/15 edges, `aria-hidden`, `pathLength="1"` with a `stroke-dashoffset` draw, `pointer-events: none`, hidden at `max-width: 900px`, in forced colours and in print. It is `--action` at 0.12 opacity. It must never change the hero's dimensions.
- **Hero depth (V8):** the graph drifts 48px as the hero leaves — `animation-timeline: scroll(root block)`, `animation-range: 0 90vh`, keyframes from `translateY(-50%)` to `calc(-50% - 48px)`, inside `@supports` + `prefers-reduced-motion: no-preference` + `min-width: 901px`. The `from` value is the literal centring transform; starting at `0` jumps the graph by half its height. It needs the explicit `animation: none` in the reduced-motion block, because the global 0.01ms duration override does not stop a scroll timeline. Nothing else on the CV parallaxes, and the profile card never moves.
- **Bridge band:** `.bridge` sits after `#portfolio-section` and before `#teaching-section`; it has no id and no `.section-head`, so the section-head count stays eight. White ground, 2px `--action` top rule, 1px `--rule` bottom rule, serif `h2`, one factual standfirst, one outline pill to `storymap.html`, and two unfilled `--action` circles at 0.12 opacity cropped by `overflow: hidden`. The circles are hidden at ≤1120px and in forced colours; the whole band is hidden in print. It is deliberately **not** ultramarine: the footer keeps the only blue field, and the band must not read as an advertisement between the register and the hire-relevant sections.
- **Interactive controls:** `.filters`, the `.filters__label` caption and `.work-more` are hidden until `site.js` adds `html.js-ready`; without JS all 21 project records are visible and the filter/load-more controls stay hidden. The label is a sibling *before* `.filters` so the existing `:first-child`/`nth-child(n+4)` filter rules stay valid; `.filters` takes its name from it via `aria-labelledby`.
- **Project register:** each record is `article.project-card[data-project-item]` with `data-project-id` and `data-categories` (subset of `platform`, `research`, `tool`, `knowledge`; the former `review` record is now `research`). Exactly one `<a class="project-card__link">` per card. The page size is 9; the count text and load-more label are derived from the visible totals. Order is editorial — do not sort or shuffle cards. Five filters remain: All work, Platforms, Research, Tools, Teaching. On hover/focus the 40px circle fills `--action` and the arrow turns `--on-dark`; `background-color` is part of the transition, so the fill and the border move together. The title underline is 1px. In forced colours the fill is dropped and the border, underline and 3px icon shift carry the state.
- **Storymap page:** `storymap.html` is a second page on the same tokens: masthead, sticky chapter rail (static and wrapping at ≤900px), five chapters on alternating white/paper grounds, a colophon and a small footer. It loads **no JavaScript**: the only motion is a scroll-driven 2px reading-progress rule under the rail, inside `@supports` + `prefers-reduced-motion: no-preference`, stopped explicitly under reduced motion. The map is one inline SVG (`map__outline`, `map__dots` for 4,161 markers, `map__terror` for 232 sites of terror drawn as squares) with `<title>`/`<desc>`; it has no pan/zoom, no tiles and no per-point links, and all its facts are repeated in prose. Never turn memorial records into decoration or a hover toy, and never add per-point addresses. Regenerate the map with `tools/storymap/build_map.py`, not by hand.
- **Knowledge transfer:** 20 `a.teaching-item` links plus one `article.publication-highlight`. These are static; no filters apply.
- **Mobile navigation:** base CSS keeps navigation in flow (usable without JS). At `max-width: 900px`, `html.nav-ready` turns the menu into a **non-modal disclosure** below the fixed header. There is intentionally no focus trap and no scroll lock; Esc, light-dismiss, `aria-expanded` and focus transfer to the target section are handled in `site.js`.
- **Scrollspy:** a rAF-throttled `getBoundingClientRect()` pass on scroll/resize sets `aria-current="location"` on the three primary nav links. No IntersectionObserver, so short or zoomed sections cannot drop the current marker. There are exactly two `IntersectionObserver`s in `site.js`: `initDrawnRules` (decorative rules and the footer graph, one pass each) and `initTypedFocus` (hero on/off screen, to gate rotation). Neither does per-frame work.
- **Evidence line:** `.evidence-band[role="group"]` holds four `.evidence-item` blocks (Role, Scope, Result, Evidence) inside each selected outcome. Because it sits inside a half-width outcome column, it is a 2×2 grid down to 640px, then a single column with a blue left rule. Keep exactly four items per band.
- **Layout breakpoints:** 1120px (hero density; section-head grid collapses to a block; bridge circles hidden; register media 88px), 900px (navigation disclosure, one-column grids, hero and footer graphs removed, CV spine static; register media 84px), 640px (stacked strips, single-column evidence, 3-column filter grid), 420px (small phones; register media 72px; register arrow 36px). The project register stays 2-up above 900px because long titles become unreadable in three columns. The asymmetric section head only exists above 1120px, so exactly 1120px is already one column. `storymap.html` has its own pair: ≤900px collapses the numeral column, stops the chapter rail sticking and wraps its links, stacks the three forms and the colophon rows; ≤640px stacks the masthead nav and turns the decade chart from nine columns into rows (`label | bar | count`).
- **German content:** German headings/cards carry `lang="de"`; preserve it when editing.
- **Images:** use WebP (keep width/height attributes). `og-cover.jpg` is the only intentional non-WebP content image. Register thumbnails are `images/portfolio/thumbs/*-224.webp`, served via `srcset`/`sizes`; the 900px sources stay in the repo for the three outcome images only. The award note uses `images/announcement/ann02-192.webp`. Derivatives are generated once with Pillow, not at runtime.
- **Print** is a feature: browser print produces a concise CV. It keeps the profile identifiers, outcomes, capabilities, method, CV and contact; it hides the project register, bridge band, teaching list, hero typed line, typed toggle, hero graph, footer graph, caret, form, footer and imprint, and prints capabilities/tag groups as two-column grids. Headings print black with the serif retained, the section head is forced back to a block (a wide sheet can exceed 1120px), `.filters__label` is hidden with the filters, tags get a `#999` border on white and the award-note tint is flattened. Every animation and transition is neutralised in print and the pseudo-element rules are forced to `transform: none`, so a rule never prints half-drawn; the CV spine prints as one complete black rule with black markers. `storymap.html` prints as a report instead: masthead nav, chapter rail, footer and the back button are removed, every chapter, both figure blocks, the numbers and the colophon stay, the map prints black, and the decade bars print as outlined columns so they survive a browser that drops background graphics.
- **Forced colours and reduced motion** have explicit blocks at the end of the stylesheet. State must never depend on colour alone (selected filters gain an underline in forced-colours mode, form success gains a check icon, the primary pill keeps a `CanvasText` border). The hero graph, footer graph, bridge circles, storymap rail progress and header progress line are removed in forced colours; caret, arrival rule, CV spine and markers, copy check and typed toggle use `CanvasText`; the storymap map prints its outline, dots and squares in `CanvasText` at full opacity, keeping shape as the distinction. Under `prefers-reduced-motion: reduce` there is no typing, caret, arrival draw, graph draw, hero drift, rule draw, spine fill, storymap progress, settle, thumbnail scale, icon shift or View Transition.
- **Register transitions:** filter changes run the synchronous `apply()` inside `document.startViewTransition` only when available and reduced motion is not requested (`view-transition-name: register` on `.project-grid`, root cross-fade suppressed); otherwise they update instantly. "Load more" is not a reveal: newly shown cards get a one-shot `.is-settling` 4px settle.
- **Reading progress:** a 2px rule is drawn by a CSS scroll-driven animation on `.site-header::after` inside `@supports (animation-timeline: scroll())`. The storymap's `.sm-rail__progress` is the same mechanism on its sticky chapter rail. No JavaScript scroll math and no new scroll listener.
- `google9857a7b25fe89ee0.html` is Search Console verification; leave it in place.
- `opencode.jsonc` contains a plaintext API key and is not covered by `.gitignore`. Check `git status` before broad staging; do not commit it.
